# iPad 用オフラインツール集

**一度ホーム画面に追加すれば、Wi-Fi が無くても起動できる**アプリを 3 つ収録。
どれも端末内で完結し、外部への通信は一切しない。

| アプリ | URL | 内容 |
|---|---|---|
| **NAVLOG WORKSHEET** | `https://hiro-76.github.io/IpadAPP/` | フライトプラン PDF の `NAVIGATION LOG` を読み取り、ETO / ATO / ALT / RMG / SAT / SPOT WND を機内で記入 |
| **RWY Wind Limit Calculator** | `https://hiro-76.github.io/IpadAPP/wind/` | 滑走路方向と横風 / 追い風 / 向かい風の制限値から、風向ごとの許容風速を計算 |
| **SWING OVERLAY** | `https://hiro-76.github.io/IpadAPP/golf/` | ゴルフスイングの動画 2 本を、体の大きさとスイングの速さをそろえて重ねて表示 |

3 つは独立した PWA なので、**それぞれ別のアイコンとしてホーム画面に追加**できる
（全部追加してもキャッシュや保存内容は干渉しない）。

---

## iPad での使い方

アプリごとに同じ手順を行う（NAVLOG は `…/IpadAPP/`、風計算は `…/IpadAPP/wind/`、
スイング重ねは `…/IpadAPP/golf/`）。

1. **Safari**（Chrome ではなく Safari）で公開 URL を開く
2. ヘッダー右のバッジが `CACHE …` → **`OFFLINE OK`** に変わるまで数秒待つ
   （この間に本体・pdf.js・アイコンを端末に保存している）
3. 共有ボタン <kbd>⤴</kbd> → **「ホーム画面に追加」**
4. 機内モードにしてホーム画面のアイコンから起動 → そのまま使える

NAVLOG で `📷 CDU読込`（カメラで CDU を読む）を機内でも使うなら、**地上にいるうちに
一度 `CDU読込` を開いて**文字認識の部品（約 9MB）を取り込んでおく（下の「CDU をカメラで読み取る」）。

> バッジの意味
> | 表示 | 状態 |
> |---|---|
> | `CACHE …` | オフライン用キャッシュの準備中（もう少し待つ） |
> | `OFFLINE OK` | 準備完了。Wi-Fi 無しで起動できる |
> | `OFFLINE` | いま通信が無い状態で動作中 |
> | `LOCAL` | Service Worker が使えない（`file://` で開いた等） |

### プラン PDF の読み込み（📄 PDF読込）

`📄 PDF読込` で `NAVIGATION LOG` を含むプラン PDF を選ぶと、WPT が並ぶ。

**2 通りの PDF に対応している。**

| PDF の作り方 | 読み取り |
|---|---|
| ディスパッチのシステムから出した**そのままの PDF** | 文字が正確なので、そのまま全 WPT・全数値が入る（推奨） |
| **コピー機やスキャナで取り込んだ PDF**（iPad で撮り直した物を含む） | コピー機側の文字認識を通っているため**文字化けが残る**。化けた分は自動で戻すが、**読めない行が数本残ることがある** |

- 日本語フォント（`90ms-RKSJ-H` など）で作られた PDF は **CMap** が無いと 1 文字も
  取り出せない。pdf.js の CMap を `vendor/cmaps/` に同梱してあるので、機内でも読める。
- 化けた文字は機械的に戻している（`■`→`1`、`」`→`J`、`工`→`I`、`。`→`.`、全角→半角）。
  元から綺麗な PDF では何も起きない。
- 行が罫線などで割れていても、数行先まで探して WPT を組み立てる。
  GS/TAS が抜けた行、名前で終わる行、`ETPl` のような小文字混じりも拾う。
- **スキャンした PDF は数値も誤認識されうる**（`06.15` が `06 5` になる等）。
  読めなかった欄は空にしてあるが、**プランの数値は必ず紙の原本と見比べること**。
  記入欄（ATO/ALT/RMG/SAT/SPOT WND）は自分で入れるので影響しない。

実測（NH109 の実物）: コピー機で作った 2 通とも **40 / 41 WPT** を復元（座標のある行は 44 / 42）。
読めなかった行はコピー機の文字認識で数字が欠けていた行。

### NAVLOG の記入ルール

| 欄 | 入力のしかた |
|---|---|
| **ETO** | 自動計算。4 桁で手入力すると**その地点を基準に以降を引き直す**（枠がアンバーの実線になる）。**空にすれば自動計算に戻る**。確定は欄の外をタップするか Enter |
| **ATO** | 4 桁（`0930`）。`NOW` ボタンで現在 UTC |
| **ALT** | 3 桁のフライトレベル（`320`） |
| **SAT** | **数字だけ入れるとマイナスになる**（`45` → `-45`）。プラス値のときだけ `+15` と符号を付ける |
| **SPOT WND** | **数字だけ続けて入れる**。欄を離れた時に `/` が入る（`24030` → `240/30`、`040135` → `040/135`）。テンキーで入力できる |
| **RMG** | **数字 4 桁で `XXX.X`**（`258`→`258.0`、`2580`→`258.0`、`0258`→`25.8`、`02580`→`25.8`）。`284.1` のように小数点を打った場合はその値。`284100` のような LB 表記も先頭 4 桁を採るので `284.1`。PLAN FUEL との差を自動表示 |

**`ATO 基準で ETO 更新`（既定 ON）** — ATO を入れた地点**より後ろ**の ETO を、その実績時刻を
起点に引き直す。ATO を入れた地点自身の ETO は動かさない（DIFF を見るため）。
ATO が複数あれば一番手前に近いものが基準になり、手入力した ETO がさらに後ろにあれば
そちらが優先される。チェックを外すとプラン通りの ETO に戻る（DIFF は変わらず出る）。

**ETP**（EQUAL TIME POINT）の地点名は紫で表示し、枠も紫にして見つけやすくしてある。

**ヘッダーの常時表示** — `T/O (Z)` の隣に、スクロールしなくても見えるように並べてある。

- **ETP1 / ETP2 … / LDG の ETA** — シートの ETO と同じ値。T/O を変えても ETO を手修正しても
  即座に追従する。タップするとその WPT まで飛ぶ（数秒緑で光る）。ATO を入れた地点は色が沈む。
- **ETOPS 代替空港の ET / LT**（**ET = EARLIEST TIME / LT = LATEST TIME**）—
  プラン PDF の `-ETP/EEP/EXP/ET.LT` の節から `CYWG/2213/0053` のような
  「空港 / ET / LT」を読み取る。
  プランの値は **STD 前提**で作られているので、**実際の `T/O (Z)` との差だけずらして表示**する。
  例: STD 0600 に対し T/O 0612 なら `+12分` として `CYWG ET 2225 LT 0105`。
  ずれている時はタグが `ETOPS +12分` になり、各欄を長押し（title）でプランの元の値も見られる。
  T/O が空、または STD が読めないプランではプランの値をそのまま出す。
  参照用の値なので `ETOPS` タグでまとめつつ、T/O や ETA より **一段小さく控えめ**にしてある
  （値 16px / 空港コードは淡いピンク）。この節が無いプランでは何も出ない。

どちらも `PDF保存` の印刷ヘッダーにも入る。

**カーソルの動き** — 記入順は同じ WPT の中で `ATO → ALT → RMG → SAT → SPOT WND`。

- **ATO に 4 桁**入れると自動で **ALT** へ進む
- **ALT に 3 桁**入れると自動で **RMG** へ進む
- RMG / SAT / SPOT WND は桁数が決まっていないので自動では進まない。
  外付けキーボードなら `Enter` で次の欄へ（行の最後まで行くと次の WPT の ATO へ）。
  画面キーボード（テンキー）には Enter が無いため、次の欄をタップするか、
  iPad の Safari がキーボード上部に出す `‹ ›` で移動する（DOM の並び順＝上の記入順）。
- 進んだ先に既に値が入っている場合は選択状態になるので、そのまま打てば上書きになる。
- `NOW` ボタンで入れた場合はカーソルを動かさない（確認してから次へ進めるように）。

**ボタンと表示の大きさ**
- `T/O (Z)` / `ETP` / `LDG` の時刻表示は同じ大きさ（値 20px / ラベル 15px）。
  `ETOPS` はその下の階層として一段小さい（値 16px / 空港コード 12px）。
- よく押す `NOW` / `📄 PDF読込` / `PDF保存` / `⇄ 引き継ぎ` / `📷 CDU読込` / 明るさ切り替えは
  同じ大きさ（15px・高さ 41px）。色は役割ごとに変えてある（NOW = 緑の塗り、
  PDF保存 = アンバーの枠、引き継ぎ = シアンの枠、CDU読込 = ミントの枠）。
- 明るさ切り替えは **`☀ DAY` / `☾ NIGHT`**。絵柄を 24px に拡大し、押すとどちらになるかを
  文字でも示すようにした（夜間表示のときは `☀ DAY` ＝押すと昼間表示）。

**NOW ボタン**
- ヘッダーの `NOW`（T/O 用）は緑で、出発時に必ず押すので探さずに届く位置に置いてある。
- 各 WPT の `NOW` は、その欄の ATO が**空なら 1 回押すだけ**で記入。
  **既に時刻が入っている場合は 1 回目で「もう一度」に変わり、続けてもう 1 回押したときだけ**
  上書きする（機内で肘が当たった等の誤操作で実績時刻を壊さないため）。
  4 秒放置するか画面をスクロールすると解除される。

### CDU をカメラで読み取る（📷 CDU読込）

CDU の **POS REPORT** の画面をカメラで撮ると、該当する WPT の欄に自動で入る。

| CDU の項目 | 入る欄 |
|---|---|
| `POS` | **参考表示のみ**（入れ先は自分で選ぶ） |
| `ATA` | **ATO** |
| `ALT`（`FL190`） | **ALT**（`190`） |
| `TEMP`（`-25°C` / `M25C`） | **SAT**（`-25`） |
| `WIND`（`180°/30KT`） | **SPOT WND**（`180/30`） |
| `POS FUEL`（`85.8`） | **RMG**（`85.8`） |

1. `📷 CDU読込` を押す（先にプランを読み込んでおく）
2. **画面の上で「入れる WPT」を選ぶ。** 既定は**まだ ATO を入れていない先頭**なので、
   順に報告していれば触らなくてよい（記入済みには `✓時刻` が付く）
3. **その場で撮る**なら、映像に出る**枠に CDU の画面を合わせて** `撮影して読み取る`、
   **撮ってある写真を使う**なら `写真から読み込む`（写真ライブラリ／ファイルから選ぶ）
4. **読み取り結果を確かめてから `反映する`**（選び直せばその場で入れ先が変わる）
5. 反映すると、**埋まらなかった最初の欄**（全部埋まっていれば RMG）にカーソルが移る

**入れ先は必ず自分で選んだ WPT。** 読み取った `POS` は照合の当てにせず、
「選んだ WPT と一致」「選んだ WPT と違います」と**参考として出すだけ**にしてある
（文字認識が POS を読み違えても、別の地点に書き込まれることはない）。

**プランと離れた値は断りを出す。** 入れ先が決まっているので、
`ALT` がプランと 4000ft 以上違う・`TEMP` が 15°C 以上違う・`RMG` が大きく違う場合は
`プランは FL360 — 確認してください` のように赤で添える。

**撮る時は枠に合わせる。** 映像の真ん中に **CDU の画面と同じ形（横 5 : 縦 4）の枠**を出す。
枠いっぱいに画面が入るまで近づけて撮ると、

- **枠の中だけを切り出して読む**ので、周りのパネル・映り込み・机が一切入らない。
- 画面が大きく写るぶん**文字が大きく写る**。読み取りで一番効くのはこれ。
- 見出しの字がどうしても読めない項目は、**枠の中の決まった場所**から読める（下記）。

枠から外れて撮ってしまった時（枠の中で字がほとんど読めない／字が枠の縁で切れている）は、
**切らずに写真全体で読み直す**ので、合わせ損ねても今まで通りに読める。

作った画像で測ると、**遠め・ボケの写真**は枠なしで 12 項目中 8 正解（4 つ空欄）・平均 4.8 秒、
**同じ条件で枠に合わせる**と 12 項目すべて正解・平均 1.6 秒になる。

- ボタンは映像の**上**にある。カメラが縦向きで映像が縦長になっても、
  ボタンが画面の外に出ない（Split View で狭くしても押せる）。
- カメラが使えない・許可していない場合でも `写真から読み込む` は使える。
- **周りが明るくても構わない。** 写真の中から**暗い CDU 画面の部分だけを切り出して**
  白黒にするので、コックピットのパネルや机の上ごと写っていても読める
  （画面いっぱいに写っている場合は切り出さない）。近づけて撮るほど確実。
- TEMP は符号が読めなくても、SAT の入力規則どおり**マイナスとして入る**
  （確認画面にも `-43°C` と符号付きで出る）。

**読み間違いへの備え** — CDU の `0` は**斜線入り（Ø）**なので、文字認識は `9` `8` のほか
`P` `D` `O` `Q` `G` `U` とも読む（`0416z` → `9416z` / `P4162`、`FL340` → `FL348` / `FL34D`）。そこで、

- **数字の並びの中の `O P Q D G U` は 0 に戻す。**
- **ATA は「FL のある行」から採る。** CDU は `CARTO  0416z  FL340` と 1 行に並ぶので、
  その行を先に見る（下の行の **ETA を掴んで別の時刻を入れてしまうのを防ぐ**）。POS も同じ行から採る。
- **1 回目は写真全体を読む**（勝手に切ると文字を捨てるため）。読み切れない時は、
  1 回目で**実際に読めた語の位置**から画面の範囲と文字の大きさを割り出し、
  そこだけを**傾きを戻して・文字が 36px くらいになるまで引き伸ばして**読み直す。
  足りない欄だけを埋める。確認画面には**読み取りに使った白黒画像**も小さく添える。
- **読めなかった項目は「場所」で読み直す。** CDU の POS REPORT は
  **見出しの 1 行下に値**という並びが決まっている。

  ```
  POS            ATA    ALT          ← 見出し
  CARTO         0416z  FL340         ← 値
  TEMP     WIND                      ← 見出し
  -43°c  324°/ 28KT                  ← 値
           POS FUEL                  ← 見出し
              85.8                   ← 値（画面の右下）
  ```

  写真全体を一度に読むと、離れた行がつながったり桁が落ちたりする（`0416z` が消える、
  `-42°C` が `-1°C` になる、`22KT` が `4KT` / `227KT` になる）。そこで**足りない項目**は、
  1 回目に読めた語の中から**見出しの字の位置**を探し、**その 1 行だけを切り出して**
  引き伸ばし、読む字を絞って（FUEL なら数字だけ）読み直す。
  見出しの字が読めていない時は、値そのものの形（`FL340` `28KT` `43C`）を手がかりにする。
  それでも駄目な項目は、最後に**その項目だけ**を狭く切り出して読む
  （隣の値が入らないぶん大きく引き伸ばせる。白黒の付け方も、ふつう・薄い文字向け・
  **太ってくっついた文字向け**の 3 通りを試す）。
  この読み方で入れた値には `見出しの位置から読み取り・要確認` と赤で断る。
- **枠に合わせて撮った時は、最後に「枠の中の場所」から読む。** POS REPORT は
  行も桁も決まった位置にあるので、見出しの字が読めなくても
  「枠の左上を 0、右下を 1 として、TEMP の値はこの辺り」と決め打ちで切り出せる。
  位置は実機の写真で測った値に余裕を足した物で、**枠そのもの**を基準にする
  （切り出しは枠より少し広く取るので、そちらを基準にすると 1 行ずれる）。
  隣を巻き込むと読み違えるので、TEMP の帯は WIND の手前で止めてある。
  ここで入れた値には `枠の中の位置から読み取り・要確認` と断る。
- **写真の傾きを戻してから切り出す。** 手持ちで撮ると必ず少し傾き、行を横長に切り出すと
  端で行が外れる。同じ行で隣り合う語の中心を結んだ角度（中央値）で**真っ直ぐに戻す**。
- **切り出した 1 行は、点のかたまりごと掃除する。** 周りに仲間のいない点だけでなく、
  **文字より小さいかたまり**（埃・画面のムラ）をまとめて消す。
  白黒に分ける窓の大きさも**文字の高さ**から決める（細長く切った時に窓が小さくなりすぎて
  太い文字の内側が抜けるのを防ぐ）。
- **CDU の FUEL は必ず小数 1 桁**なので、**小数点が薄くて消えて `755` と読めても `75.5`** に戻す
  （ただし場所だけを頼りにした時は、小数点が読めた並びしか採らない。
  `0454` のような時刻を FUEL として入れないため）。
- **プランと大きく食い違う値は、読み違えを疑ってもう一度「場所」で読む。**
  `ALT` が 4000ft 以上・`TEMP` が 15°C 以上・`RMG` が大きく違う・`WIND` の向きが 90° 以上違う、
  といった時に読み直し、違う値が出たら**切り出して読んだ方**を採って
  `読み -1 を場所から読み直した・要確認` と元の読みも見せる。
- **桁が落ちた／増えた読みを見分ける。**
  **巡航高度（FL200 以上）で SAT が -15°C より高いことはない**ので、
  `-42°C` が `-1°C` になった読みはその場で分かる。読み直しても直らなければ
  **値として入れず**、`読み -1°C は値としておかしい` と出して手入力に回す。
  風速も**プランの半分以下・2 倍以上**なら桁違いとみなして読み直す
  （`22KT` → `4KT` / `227KT`）。200KT を超える読みは最初から採らない。
- **ATO / ALT / SAT / SPOT WND の 4 つが揃った時点で読み直しを打ち切る**ので、
  ふつうに撮れていれば 1 回（数秒）で終わる。揃わない時だけ 2 回目・3 回目に進む。
- 読み取り中は **`読み取り中 2/3  54%`** と進み具合が出て、**`やめる`** で止められる。
  **画面を閉じれば読み取りも文字認識も片付く**（裏で走り続けて次を遅くすることはない）。
- **映像が真っ暗なまま撮ると、読みに行かずにその場で知らせる**
  （他のアプリがカメラを使っていると真っ暗になる。`写真から読み込む` で回避できる）。
- **ATA は必ず「FL と同じ行」か「ATA と書かれた行」から採る。**
  そこに読める時刻が無ければ**空欄**にする（画面の下にある **ETA を掴んで
  別の時刻を入れてしまうのを防ぐ**）。POS も同じ考えで、`POS` の行か
  その次の行だけを見る（`EST` / `NEXT` の地点名を拾わない）。
  埋めた値は **1 回目 → 2 回そろった値 → 1 回だけの値**の順で採り、
  1 回だけの値には「読み直しで取れた値・要確認」と赤で断る
  （白黒を反転して読んだ回の値は、1 回だけなら採らない）。

- **値としてありえない形なら、直せるかどうかを試す。** 時刻は 24 時制として成立するか、
  風向は 360 以下か、FL は 10 の倍数か。`9416` → `0416`、`FL348` → `FL340`、`924` → `024`。
  直す文字数が一番少ない形を採り、**直した所は確認画面に赤で「読み 9416 を補正」と出す**。
- **どう直しても筋が通らない値は入れない。** 空欄（`読み取れず`）にして、
  読んだ文字だけを添える。**黙って間違った値を入れることはしない。**
- 埃や映り込みは前処理で落とす（周りに仲間のいない点は文字とみなさない）。
- 白黒に分ける境目は**周りの明るさから決める**（写真全体の平均ではなく局所平均）。
  ベゼルや操作パネルが明るく写り込んでも、画面の中の文字が背景側に沈まない。

それでも文字認識は万能ではない。**確認画面の目視は省かないこと。**

- POS は多少の誤読を吸収して**一番近い WPT**に当て、**参考表示**に使う（入れ先は変えない）。
  形の似た文字（`O`/`Q`/`D`/`0`、`I`/`L`/`1`、`S`/`5`、`B`/`8`、`Z`/`2`、`G`/`6`）をまとめ、
  **前後に余計な文字が付いても**（`LCARTQ` → `CARTO`）、**2 文字違いまで**なら拾う。
  同じ名前の地点が航路に 2 つある時は、**まだ ATO を入れていない方**を選ぶ。
  それでも見つからない時は「プランにありません」と出るので、撮り直すか手で入れる。
- 読み取れなかった項目は `読み取れず` と赤く出て、その欄は書き換えない。
- **OCR は誤読する**。反映前の確認画面で必ず目視してから押すこと。
- 反映後は `ATO 基準で ETO 更新` が効いて以降の ETO が引き直される（チェック時）。

**オフラインで使うための準備** — 文字認識の部品（約 9MB）は、アプリ本体とは別に
**`CDU読込` を開いた時に取り込み**、以後は端末に残る（アプリを更新しても消えない）。

- **出発前に地上で `📷 CDU読込` を一度開くだけでよい。** 画面を開いた時点で取り込みが始まり、
  終わると「取り込みました。次からは電波が無くても読めます」と出る（撮影しなくてよい）。
- 取り込み済みなら、開いた時に「文字認識の部品は端末にあります」と出る。
- まだ取り込んでいない状態でオフラインだと、その旨を赤で知らせて撮影は止まる。
- 機内では**端末に入れた物だけを使う**（部品を blob にして文字認識に渡すので、
  ネットワークにも Service Worker にも取りに行かない）。
  Service Worker を止めた状態・通信を切った状態での読み取りも試験で確認済み。

カメラは背面カメラを使う。初回は iOS がカメラの許可を聞くので `許可` する。

### 別の iPad へ引き継ぐ（QR コード / ネットワーク不要）

飛行中に別の iPad へ記入内容を渡して、続きから書ける。**Wi-Fi も AirDrop も使わない。**
画面に出した QR をもう一方の iPad のカメラで読むだけ。

1. 渡す側: `⇄ 引き継ぎ` → **QR で渡す**
2. 受け取る側: `⇄ 引き継ぎ` → **QR で受け取る** → 相手の画面にカメラを向ける
3. 読み取れると自動で取り込み、**未記入の最初の WPT にカーソルが移る**

QR は **記入内容 → プラン本体** の順に流れる（0.9 秒ごとに自動で切り替わり、繰り返す）。

| 受け取り側の状態 | 動き | 読む枚数 |
|---|---|---|
| **同じプランを読み込み済み** | 記入内容だけ取り込む | 前半だけ（記入 6 WPT で 1 枚、全 71 WPT でも 3 枚） |
| **違うプラン / プラン未読込** | 指紋の不一致を知らせて止まる。**新規読み込み（強制）** を押すと**便名も全 WPT も記入内容も丸ごと置き換える** | 全部（全 71 WPT 記入で 10 枚 ≒ 9 秒 / 1 巡） |

- 渡すのは ATO / ALT / RMG / SAT / SPOT WND / 手修正した ETO / T/O / `ATO 基準で ETO 更新`、
  および便名・日付・各 WPT（名前・緯度経度・TC/MC・GS/TAS・DIST・CTME/RTME・ALT・FUEL・
  TMP・WIND・MW/TP・ISA）。
- **プランを何も読み込んでいない iPad でも、強制で受け取ればそのまま使える**（PDF 不要）。
- 指紋（便名 - 日付 - WPT 数）が一致する限り拒否は起きないので、通常運用では前半だけで一瞬で終わる。
- カメラが使えない環境では `⇄ 引き継ぎ` → **ファイルで渡す** で JSON を書き出し、
  受け取り側が `JSON読込` で開く。

### 記入内容の自動保存

- **NAVLOG**: 入力した T/O・ATO・ALT・RMG・SAT・SPOT WND と読み込んだプランを
  端末内（localStorage）に自動保存。iOS がアプリを終了させても、次の起動時に
  「前回の作業を復元しました」と表示して続きから使える（不要なら `破棄`）。
  **最後に触っていた欄までスクロールして、その欄にカーソルを戻す**ので、
  アプリが落ちても探し直さずに続きから書ける（該当の WPT が数秒間緑で光る）。
  長期保存したい場合は従来どおり `JSON保存` を使う。
- **RWY Wind**: 滑走路・横風 / 向かい風 / 追い風の選択を保存し、次回起動時に
  そのまま復元して結果表を出し直す。

## スイング動画を重ねる（SWING OVERLAY）

`…/IpadAPP/golf/` を開く。**2 本のスイング動画を、体の大きさ（縮尺）とスイングの速さ
（タイミング）をそろえて 1 枚に重ねる**ためのアプリ。動画は端末から出ない。

### 手順

1. **動画を読み込む** — `A ＝ 基準`（お手本や過去の自分）と `B ＝ 重ねる方` に動画を 1 本ずつ選ぶ。
   選んだ瞬間からコマに展開する（3〜6 秒に切り詰めた動画だと速い）。
2. **体の大きさをそろえる** — 各動画に**頭の線・足元の線・体の中心線**が出る。
   自動で当たりが付いているので、ずれていれば指でドラッグして直す。
   2 本の線の間隔（＝身長）の比で B を拡大・縮小して重ねる。撮影距離が違っても合う。
   カメラの向きが逆（右打ち / 左打ちの見え方が逆）なら `左右反転`。
3. **スイングの速さをそろえる** — `アドレス / トップ / インパクト / フィニッシュ` の
   4 つの節目を動画ごとに決める。`自動検出` が動きの大きさから推定するので、
   ずれていたら節目のボタンを選んでスライダーで直す。
   バックスイングとダウンスイングの秒数・比（テンポ）もここに出る。
4. **重ねて見る** — 再生すると、**節目から節目までの時間を伸縮させて**両者が
   同じ局面で並ぶように動く。テンポが違う 2 人でも、アドレスはアドレス、
   トップはトップ、インパクトはインパクトで重なる。

### 重ね方の選択

| 設定 | 内容 |
|---|---|
| **合わせ方** | `4 つの節目でそろえる`（既定）／`インパクトだけそろえる`（速さはそのまま）／`そろえない`（実際の速さで並走） |
| **テンポの基準** | どちらの速さで再生するか。基準にした方は等速、もう片方が伸縮する |
| **表示** | `重ねる` / `横に並べる`（並べる時も身長と地面をそろえる） |
| **重ね方** | `普通に重ねる` / `差分（ズレが光る）` / `スクリーン` / `比較（明）` / `乗算` |
| **色分け** | A を水色、B を桃色に染めて、どちらの体か見分けやすくする |

- 1 本指のドラッグで **B の位置を微調整**、2 本指で画面全体の拡大・移動。
- `大きさ微調整` は自動で決まった倍率の上に掛ける微調整（0.6〜1.6 倍）。
- `この重ね画像を保存` で今の 1 枚、`4 コマ比較を保存` でアドレス / トップ /
  インパクト / フィニッシュを 2×2 に並べた PNG を書き出す（「ファイル」アプリに入る）。

### 撮るときのこつ

- **カメラは固定**（三脚や壁に立てかける）。手持ちで揺れると背景ごと動き、
  自動検出の精度が落ちる。
- 2 本とも**同じ方向から**撮る（正面なら正面、飛球線後方なら後方）。
- 足元から頭まで画面に入れる。上下が切れていると身長で合わせられない。
- 明るい所で撮る。逆光や暗所は動きの検出が鈍る。

## 公開（GitHub Pages）

Service Worker は `https://` でのみ動くため、どこかに HTTPS で置く必要がある。
GitHub Pages が最も簡単:

1. このブランチを push（済）
2. GitHub の **Settings → Pages**
   - Source: `Deploy from a branch`
   - Branch: このブランチ / フォルダ `/ (root)`
3. 1〜2 分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される
4. その URL を iPad の Safari で開く（上の「iPad での使い方」へ）

サブディレクトリ配信でも動くように、参照は全て相対パスにしてある。

### 検索避け

各アプリの `index.html` に `<meta name="robots" content="noindex, nofollow, …">` を入れてあるので、
Google などの検索結果には出ない（＝ URL を知っている人だけが辿り着く）。
`<meta name="referrer" content="no-referrer">` も入れてあり、リンクを踏んで他サイトへ
移動しても参照元として URL が漏れない。

**これは認証ではない**。GitHub Pages は Free / Pro / Team プランでは必ず全世界公開で、
アクセス制御は Enterprise Cloud 限定。リポジトリが public なのでプロフィールから
URL は推測できる。本当に人を限定したい場合は、リポジトリを private にする
（GitHub Pro 以上）か、Cloudflare Pages + Cloudflare Access のような認証付きホスティングへ移す。

なお `robots.txt` はクローラーが `https://<ユーザー名>.github.io/robots.txt`（ドメイン直下）
しか読まないため、プロジェクトページ配下に置いたものは無視される。実際に効いているのは
上の `meta` タグ。サイト全体で止めたい場合は `<ユーザー名>.github.io` リポジトリの直下に置く。

## オフライン化のためにやったこと（NAVLOG）

- **pdf.js を CDN 参照からローカル同梱へ** — 以前は `cdnjs.cloudflare.com` から
  本体と worker を取得していたため、オフラインでは PDF 読込が失敗していた。
  互換性の高い legacy build を `vendor/` に同梱し、worker も相対パス指定に変更。
- **Service Worker (`sw.js`)** — `index.html` / `manifest` / `vendor/*` / `icons/*` を
  インストール時に一括キャッシュ。以後はキャッシュ優先で応答するので、
  機内でホーム画面から起動しても確実に開く。
- **PWA メタデータ** — `manifest.webmanifest`、`apple-mobile-web-app-capable`、
  `apple-touch-icon`、`apple-mobile-web-app-title` を追加。ホーム画面から
  Safari の UI 無し（standalone）で起動する。ステータスバーと重ならないよう
  ヘッダーに `env(safe-area-inset-*)` を反映。
- **記入内容の自動保存 / 復元** — 入力ごと（400ms デバウンス）と
  バックグラウンド移行時に localStorage へ保存し、起動時に復元。
- **通信 / キャッシュ状態バッジ**と**更新通知** — 新しいバージョンが公開されたら
  「更新」ボタンを表示し、押したときだけ差し替える（記入中に勝手にリロードしない）。
  テーマ（Day/Night）も端末に記憶する。
- ついでに、重複定義されていた `ensureWorker()` / `pdfToText()` を 1 つに整理し、
  CSV 出力の ETO 列が常に空になっていた参照ミス（`getElementById('eto…')`）を修正。

## 記入まわりの修正（v1.0.2）

- **ETO を BackSpace で消すと `0000` に張り付いて直せなくなる不具合を修正。**
  1 文字消すたびに途中の `123` を `01:23` と解釈して欄に書き戻していたのが原因。
  入力中は書き戻さず、欄を離れた時（または Enter）に確定する方式に変更した。
  ついでに **空欄にすれば自動計算に戻せる**ようにし、手入力した ETO は枠の色で
  分かるようにした。
- **ETP** の地点名を紫（`--etp`）にし、ストリップの枠も紫に。
- **SPOT WND** は数字だけ続けて入力すれば、欄を離れた時に `/` が入る（先頭 3 桁が風向）。
  入力中に値を書き換えると iOS が直前の文字を二重に挿入してしまい、`23023` が
  `230/223` になる不具合が出たため、整形は確定時のみにしてある。
  PLAN 側の `WIND` 表示も同じ書式（`285081` → `285/081`）に揃えた。
- **SAT** は数字だけ入力するとマイナス扱い（`45` → `-45`）。プラス値は `+15` と入力。
- **印刷（PDF保存）に ETO が出ていなかったのを修正。** 印刷用の値コピーが
  ATO / ALT / RMG / SAT / SPOT のみで ETO を含んでいなかった。ETO は記入欄では
  なく計算値なので白地・黒文字で印字し、手入力した ETO には `*` を付けている。

## オフライン化のためにやったこと（RWY Wind Limit Calculator）

- `wind/` に移し、**同じ方式で PWA 化**（`manifest.webmanifest` / `sw.js` /
  `apple-touch-icon` / safe-area 対応 / 通信・キャッシュ状態バッジ / 更新通知）。
  元々外部ファイルを読んでいないので、キャッシュ対象は本体とアイコンだけ。
- 滑走路・各制限値の選択を localStorage に保存し、起動時に復元して自動で再計算。
- **計算ロジック（sin / cos による横風・追い風成分の算出、最も厳しい制限の適用）は
  一切変更していない。**
- 2 つのアプリが同じサイトに同居するため、各 Service Worker が自分の担当 URL だけを
  処理するように整理（`wind/` へのアクセスがルート側の NAVLOG に乗っ取られない、
  片方の更新で他方のキャッシュを消さない）。

## SWING OVERLAY の作り

- **コマに展開してから扱う。** 動画を 2 本同時再生して同期させるのは端末側の都合に
  左右されるので、読み込み時に `<video>` をシークしながら 1 コマずつ canvas に描き、
  `ImageBitmap` の列にしてしまう。以後の再生・コマ送り・重ね合わせは全部この列を
  読むだけなので、2 本を任意の速さでぴたりと合わせられる。
  コマ数と大きさは端末のメモリに収まるよう自動で決める（`コマの細かさ` で 3 段階）。
- **縮尺**は身長（頭の線〜足元の線）の比。線の初期値は、コマ間の差分が閾値を超えた
  画素を全コマ分積み上げた「動きの通った範囲」から出す。クラブは細くて通過画素が
  少ないので、**行ごとの画素数が多い所を体**と見て上端（頭）と下端（地面）を取り、
  横方向の中央値を体の中心にしている。合成動画での検証では頭の線の誤差は
  フレーム高の 0.3% 以内、身長比の誤差は 1.5% 以内。最終的には指で直せる。
- **タイミング**はコマ間の動きの大きさ（平均絶対差）から出す。最大の山を
  インパクト、その手前で最も静かなコマをトップ、バックスイングの山から遡って
  静けさが 2 コマ続く所をアドレス、山の後に静けさが戻る所をフィニッシュとする。
  再生時は 4 つの節目を 0〜3 の「位相」に読み替え、基準側の位相に合わせて
  もう一方の時刻を線形補間する（＝節目の間を伸縮させてテンポをそろえる）。
- 重ね合わせは canvas の合成（`difference` / `screen` / `multiply` など）。
  B の変換は「身長比で拡大 → 足元と中心を A に合わせる」の 1 つの行列にまとめてある。
- 動画そのものは保存しない（毎回選び直す）。保存するのは表示設定だけ。

## 更新のしかた

`index.html` などを変更したら、**そのアプリの `sw.js` の `VERSION` を上げて** push する
（NAVLOG は `sw.js`、風計算は `wind/sw.js`、スイング重ねは `golf/sw.js`）。次回オンラインで開いたときに
「新しいバージョンがあります → 更新」が出る。記入中に勝手にリロードはしない。

## 制限事項

- **初回だけはオンラインが必要**（キャッシュを作るため）。`OFFLINE OK` を確認してから機内へ。
- iOS は数週間使わないと保存データやキャッシュを破棄することがある。
  出発前に一度オンラインで起動しておくと確実。大事なログは `JSON保存` でファイルに残す。
- `PDF保存` は印刷ダイアログ経由（用紙は **A4 横**）。ホーム画面起動（standalone）では
  印刷が開かない場合があるため、紙／PDF が必要なときは Safari のタブで開いて実行するのが確実。
  1 WPT がページの境目で切れないようにしてあり、A4 横 1 枚あたり 7〜8 WPT 入る。
  保存時の既定のファイル名は **`NH<便名の数字> <日付>`**（`ANA0159` `18JUL26` → `NH159 18JUL26`）。
  先頭の 0 は落とし、ANA 以外の便は社名をそのまま使う。
  印刷時は ETO（手入力したものは `*` 付き）と記入済みの ATO / ALT / RMG / SAT / SPOT WND が
  そのまま出て、未記入の欄は書き込み用の黒枠になる。

### SWING OVERLAY

- 動画は**コマに展開して端末のメモリに置く**。長い動画・高いコマ設定ほど重くなるので、
  スイングの前後だけに切り詰めた 3〜6 秒の動画を渡すのが速くて確実。
  読み込みが重い端末では `コマの細かさ` を `軽量` にする。
- 読み込めるのは **iPad が再生できる形式**（iPhone / iPad で撮った MP4・MOV など）。
  再生できない形式は「読み込めなかった」と出る。
- 動画そのものは保存しない。アプリを閉じると選び直しになる（残るのは表示設定だけ）。
- 自動検出はあくまで当たり付け。**カメラが動いている / 背景が大きく動く / 極端に暗い**
  動画では外すので、頭・足元の線と 4 つの節目は目で見て直す。
